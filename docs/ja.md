## 課題

複数のAIコーディングエージェントを使っていると、半年前にちょうど今直面している問題を解決してくれたのはどのエージェントだったか、**どのプロジェクトフォルダ**で作業していたか、思い出せないことがあります。

各エージェントは会話ログを静かにディスクに保存していますが、それぞれ自分の作業ディレクトリ単位でインデックスしているため、`claude --resume` は現在いるフォルダの履歴しか知りません。履歴は失われていません。**散らばっているだけ**です。

**pawrecall** はそれらのログを1つのSQLiteデータベースにインデックスし、単一のMCPサーバー経由ですべてのエージェントに返します。パスにも、エージェントにも依存しません。

## pawrecallの特徴

- **単一ファイル・依存関係ゼロ** — Python標準ライブラリのみ。npmインストールも、Rustバイナリも、埋め込みモデルのダウンロードも、デーモンも不要。コードベース全体を10分で読めます。
- **CJK検索の完全対応** — トークナイザ不要の部分一致検索。BM-25やFTSベースのツールは日本語・中国語テキスト（分かち書きがない）で破綻しますが、pawrecallは影響を受けません。
- **逐語リコール** — LLMが圧縮した要約ではなく、実際に交わされた言葉をそのまま保存。モデル呼び出し不要（無料）で、細部まで失われません。
- **3つの提供経路** — MCP対応エージェント向けのMCPサーバー、自分用のCLI、そしてエージェントに*いつ*検索すべきかを教えるスキル。

## インストール

```bash
git clone https://github.com/chaucerj/pawrecall.git
cd pawrecall && ./install.sh          # --with-scheduler を付けると30分ごとに自動再インデックス（macOS）
```

`install.sh` が履歴をインデックスし、MCPサーバーを登録し（Claude Codeがあれば）、エージェントスキルをインストールします。sudoも不要で、ホームディレクトリの外には何も書き込みません。

必要要件：Python 3.9以上（それだけ）。

## 使い方

**任意のエージェントから**（再起動後）：

> 「前に別のAIと履歴書のプロジェクトの並び順について相談したと思う——探して。」

エージェントは `paw_search` を呼び出し → どのツールで・どのプロジェクトで・いつ話したかを確認 → 必要なら `paw_read` で会話全体を読み込みます。

**ターミナルから：**

```bash
python3 pawrecall.py search "リファクタリング"        # 全体検索
python3 pawrecall.py search "MCP" --source codex      # 特定エージェントのログのみ
python3 pawrecall.py index                            # 増分再インデックス（数秒）
```

## 仕組み

```
~/.claude/projects/**/*.jsonl ─┐
~/.codex/sessions/**/*.jsonl  ─┼─→ pawrecall.py index ─→ ~/.pawrecall/history.db
opencode.db (SQLite)          ─┘                                   │
                                                                    │ MCP (stdio)  → 任意のエージェント
                                                                    │ CLI          → あなた
                                                                    └ skill        → いつ検索するか
```

インデックスは増分式（ファイルごとにmtime/サイズを追跡）。LaunchAgentやcronで30分ごとの自動更新も可能です。なくても、好きなときに `index` を実行するだけです。

## 評価

数字を鵜呑みにしないでください — `scripts/eval.py` があなた自身のコーパスでパイプラインを測定します：

- **A. インデックス忠実度** — 元ログから逐語メッセージをサンプリングし、設計上のフィルタ後もDBに存在するか検証（目標100%）
- **B. クエリ再現率** — インデックス済みメッセージからランダムな部分文字列を切り出し、実際の検索経路で見つかるか検証。エスケープのエッジケース（`%`、`_`、引用符、CJK句読点）もテスト
- **C. ラベル付きprecision@3** — 任意。`~/.pawrecall/eval_cases.json` に正解ケースを置くだけ（`scripts/eval_cases.example.json` 参照）

```bash
python3 pawrecall.py --db /tmp/omr.db index
python3 scripts/eval.py --db /tmp/omr.db --samples 300
```

約3.2万メッセージのコーパスでの結果（macOS、2026年2月）：忠実度100%、ランダム部分文字列の再現率約90%（未命中は高頻度語のトップKウィンドウ切り捨て——文字列自体はDB内にあり、順位が窓の下に入るだけ）、厳密なラベル付きprecision@3は5/6。開発中、このハーネスは2つの実バグを発見しました（挿入順 vs タイムスタンプ順のランキング；空白で壊れる複数単語クエリ）——両方修正済みです。

## スコープ検索とセッションカタログ

`paw_search` は `project` フィルタ（ディレクトリ部分一致）を受け付けます。ツールの説明・スキル・注入されたルールを通じて、エージェントには**現在のプロジェクトに検索を限定**し、明示的な依頼があるときのみ全体検索に広がるよう指示されています。キーワードが思いつかないときは、分類済みセッションカタログを閲覧してください：

```bash
python3 pawrecall.py sessions --project jiuge-mall     # 会話ごとに1行：ソース、件数、トピック
python3 pawrecall.py sessions --source cursor          # Cursorが話したことすべて
```

MCP経由では `paw_sessions` が同じカタログをすべてのエージェントに提供します。インデックス自体はローカル限定（`chmod 600`）で、マシンの外に出ることはありません。

## FAQ（よくある質問）

**データは外部に送られますか？**
いいえ。すべてマシン上の `~/.pawrecall/` に留まります。MCPサーバーはネットワークではなくstdioで通信します。

**セマンティック検索は？** 組み込みではありません——設計上、正確な部分一致検索です（予測可能・即時・ゼロコスト）。「概念は覚えているのに言葉が出ない」クエリには、オプションのローカル埋め込みモードをロードマップに予定しています。

**どのソースがインデックスされますか？** 現在 Claude Code、Codex CLI、OpenCode、Cursor（グローバルSQLiteストアから、ワークスペースメタデータでプロジェクトマッピング）、そして Qoder（セッションタイトル・エージェントメモリ・継続サマリー——メッセージ本体はクライアント側で暗号化されているため、平文のみインデックス）。Trae は独自の暗号化データベースにチャットを保存しており、インデックスできません。ただし Trae のエージェントはCLIフォールバックでインデックスを*検索*できます。

\* Qoder：タイトル/メモリ/サマリーのみ。
新しいエージェントの追加 = パーサー関数1つ（約30行）。PRを歓迎します。

**秘密情報は保存されませんか？** 会話で交わされた内容はすべてインデックスされます。DBはトランスクリプトと同じ扱いで：`chmod 600` で作成され、ローカル限定です。
